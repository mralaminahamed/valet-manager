## 2. Config File Strategy

Two locations, site-root takes precedence:

```
Priority 1 (portable, committed to git):
  {site_root}/.valet-manager.toml

Priority 2 (centralized, not in git):
  ~/.config/valet-manager/sites/{site-name}.toml
```

**Merge rule:** keys present in the site-root file override the centralized file.
Keys absent in site-root fall through to centralized. Neither is required.

    /// Returns true if at least one field is set (file should be written)
    pub fn is_empty(&self) -> bool {
        self.memory_limit.is_none()
            && self.upload_max_filesize.is_none()
            && self.post_max_size.is_none()
            && self.max_execution_time.is_none()
            && self.max_input_vars.is_none()
            && self.max_file_uploads.is_none()
            && self.session_gc_maxlifetime.is_none()
            && self.date_timezone.is_none()
            && self.extra.is_empty()
    }

    pub fn render(&self) -> String {
        let mut lines = vec![
            "; Generated by Valet Manager — do not edit manually".to_string(),
        ];
        if let Some(v) = &self.memory_limit         { lines.push(format!("memory_limit = {v}")); }
        if let Some(v) = &self.upload_max_filesize  { lines.push(format!("upload_max_filesize = {v}")); }
        if let Some(v) = &self.post_max_size        { lines.push(format!("post_max_size = {v}")); }
        if let Some(v) = self.max_execution_time    { lines.push(format!("max_execution_time = {v}")); }
        if let Some(v) = self.max_input_vars        { lines.push(format!("max_input_vars = {v}")); }
        if let Some(v) = self.max_file_uploads      { lines.push(format!("max_file_uploads = {v}")); }
        if let Some(v) = self.session_gc_maxlifetime { lines.push(format!("session.gc_maxlifetime = {v}")); }
        if let Some(v) = &self.date_timezone        { lines.push(format!("date.timezone = \"{v}\"")); }
        for (k, v) in &self.extra                   { lines.push(format!("{k} = {v}")); }

## 4. HTTP Server Abstraction

### Supported servers and their config file locations

| Server | Config path | Reload command |
|---|---|---|
| **Nginx** | `~/.config/valet/{Nginx/,Sites/}{site}.conf` | `sudo systemctl reload nginx` |
| **FrankenPHP** (Octane) | `{site_root}/Caddyfile` or inline via `artisan octane:start` | Restart octane process |
| **FrankenPHP** (standalone) | `/etc/frankenphp/Caddyfile.d/{site}.caddy` | `sudo systemctl reload frankenphp` |
| **Caddy** | `/etc/caddy/sites/{site}.caddy` | `sudo systemctl reload caddy` |
| **Apache** | `/etc/apache2/sites-available/{site}.conf` → symlink to enabled | `sudo systemctl reload apache2` |

### Config template rendering

Each server type has a Handlebars template in `assets/templates/servers/`.

```
assets/templates/servers/
├── nginx-site.conf.hbs          (existing)
├── nginx-proxy.conf.hbs         (existing)
├── nginx-site-php.conf.hbs      (PHP-FPM backend)
├── nginx-site-octane.conf.hbs   (Octane/FrankenPHP proxy backend)
├── frankenphp-standalone.caddy.hbs
├── frankenphp-octane.caddy.hbs
├── caddy-site.caddy.hbs
├── caddy-proxy.caddy.hbs
└── apache-site.conf.hbs
```

### FrankenPHP specifics

FrankenPHP can run in two modes for a Valet site:

**Mode A — Octane backend (Nginx frontend)**
Nginx proxies to FrankenPHP running on a local port.
`artisan octane:start --server=frankenphp --host=127.0.0.1 --port={port}`
Nginx upstream: `fastcgi_pass 127.0.0.1:{port};`

**Mode B — Standalone (replaces Nginx)**
FrankenPHP handles HTTPS natively via its embedded Caddy.
Valet's dnsmasq still resolves the TLD; FrankenPHP binds to port 80/443.
Requires removing the Nginx site config and writing a `/etc/frankenphp/conf.d/{site}.caddy`.

### Caddy specifics

Caddy can serve alongside Nginx on a different port, or replace it.
When replacing Nginx: disable the Nginx site config for this domain and write a Caddy block.
Caddy auto-provisions TLS (works with valet CA if configured).

### Apache specifics

Apache VirtualHost config at `/etc/apache2/sites-available/{site}.conf`.
`sudo a2ensite {site}.conf && sudo systemctl reload apache2`
`.htaccess` editor for per-directory rules (no privilege helper needed — lives in site root).

## 5. WordPress Multisite Enablement Flow

Enabling multisite on an existing WordPress install requires changes to:
1. `wp-config.php` — add `MULTISITE`, `SUBDOMAIN_INSTALL`, `DOMAIN_CURRENT_SITE`, etc.
2. `nginx.conf` / `.htaccess` — add `rewrite` rules for multisite routing
3. Run `wp core multisite-install` or `wp core multisite-convert`

### wp-config.php constants injected for multisite

```php
define('WP_ALLOW_MULTISITE', true);
define('MULTISITE', true);
define('SUBDOMAIN_INSTALL', true);          // false for subdirectory
define('DOMAIN_CURRENT_SITE', 'myblog.test');
define('PATH_CURRENT_SITE', '/');
define('SITE_ID_CURRENT_SITE', 1);
define('BLOG_ID_CURRENT_SITE', 1);
```

### Nginx multisite rewrite rules injected into site config

For **subdomain** multisite:
```nginx
server_name *.myblog.test myblog.test;
```

For **subdirectory** multisite:
```nginx
if (!-e $request_filename) {
    rewrite /wp-admin$ $scheme://$host$uri/ permanent;
    rewrite ^(/[^/]+)?(/wp-.*) $2 last;
    rewrite ^(/[^/]+)?(/.*\.php) $2 last;
}
```

  pub async fn read_constants(wp_path: &Path) -> anyhow::Result<HashMap<String, String>>
